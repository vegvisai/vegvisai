Let AI agents use your forms (WebMCP)

WebMCP lets a visitor's own AI agent in the browser use the forms on your website: ask for a quote, book a table, send an enquiry. You register a tool in a few lines of JavaScript next to the form you already have. The customer stays on your page and clicks Send themselves.

Experimental. WebMCP is a draft from the W3C Web Machine Learning Community Group, not a W3C standard, and it can still change (draft, checked 13 October 2026). Browsers and assistants that do not know it just show your normal page, so adding it costs nothing. VegvisAI is not affiliated with OpenAI, Google, Anthropic or the W3C.

When it pays off

  • You already have an AI-readable website (level 0 and 1) with a clear contact, booking or quote form
  • Customers ask for something that needs a few details: date, number of people, size, address
  • You want the request to arrive on your own website, not through a middleman

If you have no form yet, start with an action link in your AI business card. That works with every assistant today. The generator can also make a request form with a WebMCP tool for you.

Step 1: a tool that fills in your form

Keep the form you have. Add a script on the same page (not inside an iframe) that registers a tool. The tool only fills in the fields. The customer checks them and clicks Send.

<form id="cake-order" action="/order/" method="post">
  <label>Cake <input name="cake" required></label>
  <label>People <input name="people" type="number" min="1"></label>
  <label>Date <input name="date" type="date" required></label>
  <label>Email <input name="email" type="email" required></label>
  <button>Send request</button>
</form>
<script>
if (typeof document.modelContext?.registerTool === "function") {
  document.modelContext.registerTool({
    name: "request_cake_order",
    description: "Fill in a cake order request to Eksempel Bakeri. The customer checks it and clicks Send. Nothing is paid here.",
    inputSchema: {
      type: "object",
      additionalProperties: false,
      properties: {
        cake: { type: "string", description: "Type of cake, for example birthday cake or gluten-free chocolate cake" },
        people: { type: "integer", minimum: 1, description: "Number of people the cake is for" },
        date: { type: "string", format: "date", description: "The day the customer wants to pick up the cake" },
        email: { type: "string", format: "email", description: "Where the bakery should send its answer" },
      },
      required: ["cake", "date"],
    },
    annotations: { readOnlyHint: false, consequentialHint: false },
    async execute(input) {
      const form = document.getElementById("cake-order");
      for (const k of ["cake", "people", "date", "email"]) // only the fields you declared
        if (input[k] != null) form.elements.namedItem(k).value = String(input[k]).slice(0, 200);
      form.scrollIntoView({ block: "center" });
      return "The form is filled in. Ask the customer to check it and click Send.";
    },
  });
}
</script>

Let the customer click Send. Do not call submit() from the tool. That keeps the customer in control and you out of trouble.

Step 2 (optional): a read-only tool

For things a form does not cover, such as checking free times, register a read-only tool and say so in annotations.

const controller = new AbortController();
if (typeof document.modelContext?.registerTool === "function") {
  document.modelContext.registerTool({
    name: "free_pickup_days",
    description: "Lists the next days with free capacity for cake orders. Read-only.",
    inputSchema: { type: "object", properties: {} },
    annotations: { readOnlyHint: true },
    async execute() {
      const r = await fetch("/api/free-days");
      return await r.json();
    },
  }, { signal: controller.signal }); // controller.abort() removes the tool again
}

Annotations tell the agent what kind of tool it is. They are hints that agents may use or ignore, so check everything on your server anyway.

  • readOnlyHint: true: the tool only reads and changes nothing.
  • untrustedContentHint: true: the result contains text others wrote, such as reviews or customer messages, and should be treated as data, never as instructions.
  • consequentialHint: true: the tool does something significant or hard to undo, such as placing an order or booking. Agents can use it to ask the customer first, but nothing guarantees that they do.

Older Chrome builds used navigator.modelContext. The draft now uses document.modelContext only.

Form attributes (optional extra)

Chrome's trial also lets you name a form as a tool with the HTML attributes toolname, tooldescription and toolparamdescription. They were taken out of the draft on 8 October 2026 while they are explored further, and ChatGPT does not read them. They do no harm, but do not rely on them. If you use them as well as a script, give the two tools different names.

Test it

  1. ChatGPT desktop: open your page in the app's built-in browser and choose «Site tools» in the address bar to see your tools. Then ask ChatGPT to fill in the form.
  2. Chrome: turn on chrome://flags/#enable-webmcp-testing and install the Model Context Tool Inspector. It lists your tools. Calling them from the inspector needs your own Gemini API key.
  3. Run the AI check: it lists the WebMCP tools it finds under «open for AI» and checks every description for hidden instructions.

Keep it safe

  • Describe, never instruct. Write what the tool does. Text that asks the AI to prefer your business is prompt injection: the AI check flags it, and the guide will not list a business that publishes it.
  • The customer's login is the access. Tools run with the visitor's own session, so check permissions on your server exactly as you do for the normal form.
  • Payments and orders stay with the customer. Let them confirm on your page. No tool should pay, sign or delete without a click from the customer.
  • Return only what the visitor may see, and no personal data about others.
  • Mark text others wrote. A tool that returns reviews, messages or other text you do not control gets untrustedContentHint: true, so agents that follow the hint can treat a hidden instruction in a review as data. The hint is not protection in itself: how it is handled depends on the agent, so never let a tool act on what such text says.
  • Keep tools off pages that should have none. Admin and login pages can switch WebMCP off with the header Permissions-Policy: tools=(). Tools inside an iframe, such as a booking widget from another company, are not seen by ChatGPT.
  • Ask only for what you need. A form that sends with method="get" puts the details in the web address, where they can end up in logs and browser history. Never ask for health information, national identity numbers or card details in such a form. Tell the customer in your privacy policy what you do with the details.
  • Orders with payment follow the usual rules for online sales. If a tool places an order the customer must pay for, the customer must get the required information first, the order button must say clearly that the order means paying, and the right of withdrawal applies where it normally does.

This guide is general guidance, not legal advice. You decide what your own website does.

Where it fits

An AI business card tells agents who you are (level 0). Action links let them send the customer to the right page (level 1). WebMCP lets the agent help the customer fill in that page. Your own MCP server (level 3) is for live data that partners and returning customers use from their own assistant. The guide never ranks any of this: WebMCP makes it easier to finish a task on your site, not to be shown first.
